# ADR 0045: Программа «Понимание и операция» — вход, память, продукт, долг

Status: proposed (2026-09-14)

## Цель

Система делает то, что заявляет (проверяемость, память позиций,
дисциплина поверхности), но понимает слабо (эвристики входа) и молчит
там, где могла бы рассуждать. Программа закрывает это четырьмя фазами
в порядке ROI: понимание → операция → обучающаяся память → долг.
Доктрина: понимать, а не угадывать; меньше слов — больше смысла.

## Нон-цели

- LLM на turn-пути, сеть в дефолтной сборке, само-продвижение
  пользовательского текста без решения (законы ADR-0043 в силе).
- Копирование Haskell один в один (evidence, не spec — ADR-0029).
- Переписывание V1-пинов без продуктового решения (B2 и harness
  остаются сравнимыми, пока пины не сняты явно).

## Фаза A. Понимание входа (главная дыра)

### A1. NP-чанкинг поверх морфологии
**Проблема**: сабжект — «последнее контентное слово» или первый маркер;
мульти-топики, сложные именные группы, 오류-формы теряются.
**Решение**: `qxfx0-semantic/src/noun_phrase.rs` — детерминированный
чанкер: леммы + POS + падежи из `get_runtime()` собирают именные
группы (прилагательное* + существительное + генитивные хвосты);
`PropositionParser` берёт сабжект из чанков, фолбэк — текущая
эвристика (байт-совместимость старых выходов где чанков нет).
**Приёмка**: golden-таблица 40+ входов (одно-/мульти-слово,
генитивы, опечатки, неизвестные) — чанк или честный фолбэк;
ноль дрейфа вне новых кейсов (полный гейт зелёный без обновлений,
кроме добавленных).

### A2. Композиция смыслов из юнитов фрейма
**Проблема**: юниты `InputFrame` ни во что не складываются.
**Решение**: `compose_frame_units()` — детерминированная свёртка:
агент/таргет/топик/фокус/полярность + чанки → `ComposedFrame`
(кто/о чём/фокус/тон-вопросительность). Потребители по одному:
сначала clarify (уже ест фокус), затем Connect-распаковка
(`разница между X и Y` из чанков вместо сплита по `и`).
**Приёмка**: golden-таблица композиций; Connect на чанках проходит
существующие Connect-тесты без обновлений.

### A3. Инференс глубже
**Проблема**: 10 транзитивных + 5 симметричных типов, пороги V1.
**Решение**: по одному за инкремент — (а) недостающие 5 типов
словаря с явным маппингом на Haskell-семантику, (б) `path_depth`
под V2-шкалу (аудит MEDIUM-7), (в) confidence-пол для выведенных
рёбер (поле + floor 0.25 по образцу Haskell, с дефолтами для
старых строк). Каждый пункт — отдельный коммит с гейтом.
**Приёмка**: golden-расширения parity-фикстур; инварианты в doctor.

## Фаза B. Операция и продукт (дешёвое, давно ждёт)

### B1. Публикация
Push ветки + PR (включая `force-push` slim-истории — отдельным
явным шагом с backup-бандлом, уже лежит в `/home/liskil/`).
Ревью предложения о flip (`docs/operations/first-practice-2026-09-11/flip-1.json`):
миграция M1–M4 уже приземлила механику, решение — человеческое.

### B2. Практика как режим
Еженедельные sustained-сессии (≥10 ходов, ≥2 топика, челленджи) →
`felt-export` → архив `docs/operations/practice-YYYY-MM-DD/` →
`flip-draft` поверх накопленных выгрузок. Критерий живого flip:
`sustained` по новым сессиям + B2 без регресса.

### B3. Soak-регламент
Ночной 1000-turn вместо ручных запусков (cron + `pilot.status`
архив); 30-turn smoke остаётся в CI. Порог не менять без ADR.

### B4. Первая editorial-волна
`export-pack` фийд → ручной merge первой released-группы в
pack-источники → pack-гейты (census/parse) → документированный
разбор: что вошло, что отказано и почему.

## Фаза C. Обучающаяся память (нужны решения)

### C1. Провизионные атомы (AtomAccretion-аналог)
**Блокер**: закон «пользовательский текст не самопродвигается».
**Уточнение (на решение)**: провизионный слой с TTL, порогами
(min-occurrences/min-turn-span) и каноническими коллизиями —
наблюдаемое, карантинированное, promoted только через admission
бар U5. Без решения — не строить.
**Приёмка**: golden неизвестных поверхностей (создают провизию,
не граф); TTL-эвикшн детерминирован; promotion-гейт их не видит.

### C2. Снятие V1-пинов
Только явным решением с ценой: смерть B2-сравнения и V1-бейзлайна
измерений. Пакет: удалить пины → дроп V1-модулей → гейт.

### C3. In-house grid search
Собственная калибровка saliency-весов на нашем корпусе вместо
перенесённого nudge. Процедура Haskell (`Learning/Tuning`) как
образец, Acceptance: non-regressing кандидат + doctor-bound
(±0.05 уже в инвариантах).

## Фаза D. Долг из аудитов (фон)

По одному между большими шагами, каждый — отдельный коммит:
`recovery_cause` в enum; типизированные ошибки revise/perspective;
слияние response_plan-полей (`mode`+`authority`); V1 NaN-гарды сверх
пола; `PreparedTurnContext::new` группировка при следующем касании.
Не брать: XorShift-дубли (послойные), prose-пины (контракты),
trace-ключи (контракты), `TurnOptions`-сплит (порог ~15 полей).

## Ворота приёмки (все фазы)

Релиз-гейт из AGENTS.md без послаблений + per-инкремент:
golden-таблицы нового поведения, ноль необъяснённого дрейфа
(каждый обновлённый тест — с записанной причиной),
docs-обновление в том же коммите. Запрещено: расширение скоупа
инкремента задним числом; новая продуктовая поверхность без ADR.

## Порядок и зависимости

A1 → A2 → A3 (цепочка понимания) ∥ B1–B4 (операция, anytime) →
C1–C3 (по решениям) ∥ D (фон). A не блокирует B; C1 блокируется
решением по закону; C2 — решением по пинам.
